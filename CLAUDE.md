# Caiet C++

Static web page: a C++-subset interpreter for Romanian 7th graders. TypeScript compiled by plain `tsc` to ES modules — no bundler, no framework, no runtime npm packages (the only devDependencies are `typescript` and `@types/node`). Keep it that way unless asked.

## Commands

- `npm run build` / `just build` — `src/*.ts` → `dist/`, `sw/sw.ts` → `sw.js` (both gitignored)
- `just serve` — build, then serve on :8000 (ES modules need HTTP, not `file://`)
- `just watch` — `tsc --watch`
- `npm test` / `just test` — compiles `tests/` with `tests/tsconfig.json` into `build-test/` and runs `tests/run.ts` (plain `node:assert`, no test framework)
- `npm run typecheck` — both projects, no emit

Run `npm test` after any change to `src/interp.ts`, `src/explain.ts`, `src/intro.ts`, `src/masina.ts`, `src/probleme.ts`, `src/stiva.ts` or `src/lectii.ts`, and add a case for every new language feature or error message.

## Layout

- `index.html` — markup only; loads `dist/ui.js` as `type="module"`
- `css/style.css` — all styles; colours are tokens on `:root` with a dark set under `prefers-color-scheme` and `[data-theme]`
- `src/interp.ts` — `compile(src).run(input)`, `CppError`, trace types; no DOM access
- `src/explain.ts` — `explain(line)` returns Romanian sentences for one source line; no DOM access
- `src/intro.ts` — the intro (processor, memory, variable, assignment, stack, pointer): `DEMOS` (short programs as processor steps that take boxes on top of the stack, read them, put numbers (or, for a pointer, the name of the box it points to) in them and free them at a block's `}`; `memorie()` replays them) and `INTREBARI` (quiz). Tests check each demo line and quiz answer against the interpreter. The demos are also the first examples in `#ex`; no DOM access
- `src/masina.ts` — the machine view („Pe dinăuntru”): `MASINI` (sample programs, one with new/delete, the last one a function call) and `masina(src, input)`, which runs a program with bus recording and turns each event into a `Cadru`: what the address, control and data buses carry and which way, the keyboard/screen trip, the ALU calculation, the memory boxes (with the same addresses `cout << p` prints) and a Romanian sentence; no DOM access
- `src/probleme.ts` — the pbinfo problem set: types, `note()` (what `int`-only cannot do), `matches()` search, `verifica()` runs a program on a problem's examples, `pentruPbinfo()` adapts a program for submitting on pbinfo (for file problems: `#include <fstream>` and `ifstream cin("x.in"); ofstream cout("x.out");` at the top of main, which hide the console ones), `blocuri()` splits statement text; no DOM access
- `src/stiva.ts` — the caiet's memory animations: `schimbare(prev, now)` diffs two `Snapshot`s as a stack (the common bottom part `kept`, the boxes `freed` from the top and `taken` on top, the function calls `ended`/`started`) and the heap (`heapTaken`/`heapFreed`, by name), and `spune()` says it in Romanian (with a leak note on the last step); no DOM access
- `src/lectii.ts` — the memory lessons („Stiva și heap-ul”): `LECTII`, four pages (`stiva`, `pointeri` — why pointers: a function only gets copies, so it needs addresses to change main's boxes or give several results —, `heap`, `impreuna`, also their addresses) with paragraphs (`cod`, **bold**, rendered by `html()`), an optional comparison table and programs, each with a note and what it must do (`asteapta`: its output, a run-time error, or the boxes left on the heap), and „Verifică-te” questions (`intrebari`, rendered like the intro quiz in `#lQuiz`) whose right answer tests check by running their code; tests run them all. The stack is a pile of plates, the heap a cloakroom (coat = heap box, ticket = pointer, `delete` = giving the ticket back). The programs are also examples in `#ex`; no DOM access
- `probleme/probleme.json` — 273 class-9 problems from pbinfo.ro, generated by `node tools/probleme.mjs <export.json>` (trims fields, turns the few LaTeX formulas into plain text). Regenerate it rather than editing by hand
- `src/ui.ts` — section menu, editor, highlighting overlay, run button, stepper with the stack and the heap side by side (`#stack` holds a „Stiva” column of frames and a „Heap” column), machine view (heap boxes after the stack, under a divider) (packets animated along the buses with CSS), examples, localStorage draft, problems section (list, statement, check bar, „Trimite pe pbinfo” — copies the adapted program and opens the problem on pbinfo.ro to paste and submit there, since a static page cannot submit for the logged-in student —, the statement column beside the editor), phone view (tabs, key row, viewport fit)
- `tests/run.ts` — tests for the DOM-free modules
- `sw/sw.ts` — service worker, compiled as a classic script (no imports/exports) with the WebWorker lib by `sw/tsconfig.json`, emitted to the repo root so its scope is the whole site. Its `SHELL` list must name every file the page needs offline; bump `CACHE` if you remove files from it
- `manifest.webmanifest`, `icons/` — PWA manifest and icons (PNG rendered from `icons/icon.svg`)
- `tsconfig.json` — app build (DOM lib, no Node types); `tests/tsconfig.json` extends it with Node types
- `.github/workflows/pages.yml` — typecheck + test on push/PR; deploy to GitHub Pages from `main`. Its "Assemble site" step lists every published file; add new top-level files there too

Imports use `.js` extensions (`NodeNext` resolution) so the emitted files run unchanged in the browser and in Node. `interp.ts`, `explain.ts`, `intro.ts`, `masina.ts`, `probleme.ts`, `stiva.ts` and `lectii.ts` must stay free of DOM and Node APIs.

## Interpreter design

- `lex()` produces tokens `{t, v, line, n?}` (`n` is the value of a `num` token); `#` lines are skipped but `#include <iostream>` is remembered.
- `compile()` is a recursive-descent parser that emits closures directly (no AST). Variables are resolved at compile time to a place: `G[o]` for globals, `fr[o]` in the frame of the function call running now (a fresh `fr` per call, so recursion works). Those hold slots in a flat `mem` array, given out at run time by `box()` when the declaration runs and given back at `}` or at the end of a call, except slots whose address was taken (`&`), which are never reused, so a dangling `*p` is still caught. `undefined` means "declared, no value yet". An `Expr` closure that names a box (a variable or `*p`) carries `at()`, returning its slot, so it can be assigned to; `ptr` marks pointer-typed expressions (checked at compile time). A pointer's value is the target slot + 1, 0 being `nullptr` (the address shown comes from `pos`, the box's place on the stack in 4-byte places; a long long takes two); snapshots give pointers a 4th field naming the target.
- The heap: `new int`/`new int(x)`/`new int()`/`new long long(…)` (`newBox()`) takes a box with `hbox()`: a fresh slot (never reused, so a pointer to a deleted box is caught), named „heap 1”, „heap 2”… (`hn`), `heap[s]` set, placed at the first free heap place big enough (`pos`, address `adresaHeap()` from 0x8000; a deleted box's place is reused). `hlive` holds the live heap boxes by address; `delete p;` (a statement) removes one (`delete nullptr` does nothing). Heap boxes outlive `}` and function calls; snapshots list them in `heap` (`HeapView`), bus memory includes them (`Box[5]`), and boxes left at the end are a leak the UI points out.
- Values are `Val = number | bigint`: int and pointers are numbers, long long is a bigint (`BigInt.asIntN(64, …)` wrap). Every `Expr` knows at compile time whether it is `ll`; `as()` converts (int → long long as in C++ arithmetic, long long → int keeps 32 bits), `truth()` turns a condition into 0/1.
- Functions (`Fn`): header (type `int`/`long long`/`void`, value or pointer parameters), optional prototype, body. A call evaluates the arguments, pushes the parameters as boxes, runs the body, takes `retVal`, drops the frame. `main` is a `Fn` too. Calls nest JS closures, so very deep recursion hits the JS stack (a `RangeError`, turned into a friendly run-time error; a few hundred to ~2000 calls).
- Statement closures return a `Flow`: 0 (normal), 1 (break), 2 (continue), 3 (return).
- `tick(line)` runs at each statement/loop turn: enforces the 20M step limit and pushes a `Snapshot` `{line, vars, out, calls}` (`calls` = the functions running, main first; a local's `VarView[4]` is its index there) to `trace` (first 2000 steps). The UI replays `trace` for the stepper; `live` tracks which slots are currently in scope.
- `compile(src, { bus: true })` also records `BusEvent`s (`fetch` a line, `decl` a box, `read`/`write` a box, `alu`, `in`, `out`, `free` at `}` or at the end of a call (`fn`), `call`, `ret`), each with the live memory after it, into `run().bus` (first 1500; `busCut`). The flag is fixed at compile time: without it the closures are the plain ones, so normal runs pay nothing. Keep the event order real: the box appears before its first value, a calculation before the write of its result.
- Errors are `CppError(msg, line, kind)`, `kind` being `'compile'` or `'run'`. On a runtime error `run()` attaches `out`, `trace`, `end`, `cut` and `bus` before rethrowing.

## Language rules (deliberate)

- Only `int` (32-bit wrap), `long long` (64-bit wrap; a literal over 2147483647 is long long, `LL` suffix, `(long long)`/`(int)` casts) and pointers to them (`&a`, `*p`, `nullptr`, `==`/`!=`; no pointer arithmetic, no `int**`, no references). `cin` into an int of a number that does not fit is a runtime error pointing to long long. Functions return `int`/`long long`/`void` and take value or pointer parameters; they are declared above their use (prototypes allowed); no overloading, no default arguments, no library functions. `cout << p` prints a made-up address: `0x1000` + 4 per place on the stack (8 for a long long), so a box declared after a `}` gets the address of a box freed there (as the intro says); a pointer to a freed box keeps printing its old address. Using `*p` when p is `nullptr` or its box has left the stack is a runtime error. `new`/`delete` give heap boxes (no `new int[n]`, no `new int*`, functions still cannot return pointers); `delete` of a stack box, deleting twice, `*p` after delete and reading a heap box with no value yet are runtime errors. No arrays (`[` is rejected by the lexer with a friendly message), floats, chars, strings. Unsupported things must fail with a friendly Romanian message, never a generic parse error.
- `#include <iostream>`, `using namespace std;` and `int main()` are required, so programs also compile in a real compiler.
- Reading an uninitialised variable is a runtime error (stricter than real C++, on purpose).
- `cin` past the end of input is a runtime error.

## Conventions

- All user-facing text is Romanian, with proper diacritics (ș, ț with comma below) and „ghilimele” quotes. Wording targets a 13-year-old: short sentences, no jargon.
- The highlight overlay depends on the textarea and `#hl` sharing font, 16px/24px line metrics and 12px padding. Change them together (also the `24` and `12` constants in `src/ui.ts`).
- The page must work at phone width and in both light and dark themes.
- Sections: the page shows one `[data-sec]` section at a time (`.on`): `start` (the intro), `caiet` (editor + run + stack), `probleme`, `memorie` (the lessons on the stack and the heap: one page at a time, its address `#stiva`/`#pointeri`/`#heap`/`#impreuna` instead of `#memorie`, the last one in `caiet.lectie`; each program runs with ▶ Rulează, replays with ⏵ Redă or the step bar, memory drawn by the same `drawMem()` as the caiet, always animated; „Schimbă-l în caiet” opens it as an example), `masina` (the machine view), `ajutor`. The menu (`#menu`, links `data-go`) is a sticky top bar on a computer and a ☰ drop-down on a phone (`body.menu-open`). `sec(name)` switches and puts `#name` in the address (Back works); the first section is the address's, else the last one used (`caiet.sec`), else `start` until „Am înțeles” sets `caiet.intro`. `body[data-at]` names the current section (the document picker and Run show only in `caiet`). Don't put `data-sec` or a class named like a section/menu rule on `body`.
- While a problem is in the editor its statement stays at hand: `#enunt` (`statement(…, here=true)`, the same renderer as `#pView`) is a sticky column left of the editor (`.grid.wp`; `#eTog` hides it, remembered in `caiet.enunt`) and the `enunt` tab on a phone.
- Phone view (`@media (max-width:760px), (pointer:coarse) and (max-height:500px)` in CSS, `MOBILE` in `src/ui.ts`; keep them identical): `.wrap` becomes a fixed full-screen app sized from `visualViewport` (`--app-h`/`--app-top`); inside the `caiet` section the `[data-pane]` parts show one at a time (`.on`) via the bottom `#tabs` (`enunt` only while solving a problem, `cod`, `rulare`, `pasi`; `tab()` also opens the `caiet` section); the problems section shows either the list or a statement (`.probs.open`); `#keys` (C++ keys and snippets) appears while the editor is focused. `body.editing` = editor focused, `body.kb` = keyboard open (tabs and explanation hidden). `.tabs`, `.keys`, `.mob` are hidden on desktop. Textareas must stay at 16px or iOS zooms on focus.
- All URLs stay relative (the site is served from `/caiet-cpp/` on GitHub Pages).
- Memory animations: while a problem is in the editor, „Animații în memorie” (`#pAnim` in the problem bar, remembered in `caiet.anim`) makes the stack view slide in the boxes taken at each step (`.nou`; stack boxes show their address, `VarView[5]`), fade out the freed ones (`.plec`, with whole frames when a call ends), say what happened in `#sMem`, and show `#sPlay` (⏵ Redă); ▶ Rulează then plays the steps from the start. Any manual step, a new run or the last step stops the playback. `prefers-reduced-motion` turns the movement off.
- The editor holds one document at a time, chosen in `#ex`: `mine` (the free draft, `caiet.code`/`caiet.inp`), an example (by index, read-only: editing it turns it into `mine`) or a problem (`p<id>`, its own draft in `caiet.p<id>`/`caiet.p<id>.in`). Problems solved on all examples are kept in `caiet.rezolvate`.
