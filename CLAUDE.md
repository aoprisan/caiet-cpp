# Caiet C++

Static web page: a C++-subset interpreter for Romanian 7th graders. TypeScript compiled by plain `tsc` to ES modules — no bundler, no framework, no runtime npm packages (the only devDependencies are `typescript` and `@types/node`). Keep it that way unless asked.

## Commands

- `npm run build` / `just build` — `src/*.ts` → `dist/`, `sw/sw.ts` → `sw.js` (both gitignored)
- `just serve` — build, then serve on :8000 (ES modules need HTTP, not `file://`)
- `just watch` — `tsc --watch`
- `npm test` / `just test` — compiles `tests/` with `tests/tsconfig.json` into `build-test/` and runs `tests/run.ts` (plain `node:assert`, no test framework)
- `npm run typecheck` — both projects, no emit

Run `npm test` after any change to `src/interp.ts`, `src/explain.ts`, `src/intro.ts`, `src/masina.ts` or `src/probleme.ts`, and add a case for every new language feature or error message.

## Layout

- `index.html` — markup only; loads `dist/ui.js` as `type="module"`
- `css/style.css` — all styles; colours are tokens on `:root` with a dark set under `prefers-color-scheme` and `[data-theme]`
- `src/interp.ts` — `compile(src).run(input)`, `CppError`, trace types; no DOM access
- `src/explain.ts` — `explain(line)` returns Romanian sentences for one source line; no DOM access
- `src/intro.ts` — the intro (processor, memory, variable, assignment, stack, pointer): `DEMOS` (short programs as processor steps that take boxes on top of the stack, read them, put numbers (or, for a pointer, the name of the box it points to) in them and free them at a block's `}`; `memorie()` replays them) and `INTREBARI` (quiz). Tests check each demo line and quiz answer against the interpreter. The demos are also the first examples in `#ex`; no DOM access
- `src/masina.ts` — the machine view („Pe dinăuntru”): `MASINI` (sample programs) and `masina(src, input)`, which runs a program with bus recording and turns each event into a `Cadru`: what the address, control and data buses carry and which way, the keyboard/screen trip, the ALU calculation, the memory boxes (with the same addresses `cout << p` prints) and a Romanian sentence; no DOM access
- `src/probleme.ts` — the pbinfo problem set: types, `note()` (what `int`-only cannot do), `matches()` search, `verifica()` runs a program on a problem's examples, `blocuri()` splits statement text; no DOM access
- `probleme/probleme.json` — 273 class-9 problems from pbinfo.ro, generated by `node tools/probleme.mjs <export.json>` (trims fields, turns the few LaTeX formulas into plain text). Regenerate it rather than editing by hand
- `src/ui.ts` — editor, highlighting overlay, run button, stepper/stack, machine view (packets animated along the buses with CSS), examples, localStorage draft, problems section (list, statement, check bar), phone view (tabs, key row, viewport fit)
- `tests/run.ts` — tests for the DOM-free modules
- `sw/sw.ts` — service worker, compiled as a classic script (no imports/exports) with the WebWorker lib by `sw/tsconfig.json`, emitted to the repo root so its scope is the whole site. Its `SHELL` list must name every file the page needs offline; bump `CACHE` if you remove files from it
- `manifest.webmanifest`, `icons/` — PWA manifest and icons (PNG rendered from `icons/icon.svg`)
- `tsconfig.json` — app build (DOM lib, no Node types); `tests/tsconfig.json` extends it with Node types
- `.github/workflows/pages.yml` — typecheck + test on push/PR; deploy to GitHub Pages from `main`. Its "Assemble site" step lists every published file; add new top-level files there too

Imports use `.js` extensions (`NodeNext` resolution) so the emitted files run unchanged in the browser and in Node. `interp.ts`, `explain.ts`, `intro.ts`, `masina.ts` and `probleme.ts` must stay free of DOM and Node APIs.

## Interpreter design

- `lex()` produces tokens `{t, v, line, n?}` (`n` is the value of a `num` token); `#` lines are skipped but `#include <iostream>` is remembered.
- `compile()` is a recursive-descent parser that emits closures directly (no AST). Variables are resolved at compile time to slots in a flat `mem` array; `undefined` means "declared, no value yet". An `Expr` closure that names a box (a variable or `*p`) carries `at()`, returning its slot, so it can be assigned to; `ptr` marks pointer-typed expressions (checked at compile time). A pointer's value is the target slot + 1, 0 being `nullptr` (slots are never shared, which is how `*p` on a freed box is caught; the address shown comes from `pos`, the box's place on the stack); snapshots give pointers a 4th field naming the target.
- Statement closures return a `Flow`: 0 (normal), 1 (break), 2 (continue), 3 (return).
- `tick(line)` runs at each statement/loop turn: enforces the 20M step limit and pushes a `Snapshot` `{line, vars, out}` to `trace` (first 2000 steps). The UI replays `trace` for the stepper; `live` tracks which slots are currently in scope.
- `compile(src, { bus: true })` also records `BusEvent`s (`fetch` a line, `decl` a box, `read`/`write` a box, `alu`, `in`, `out`, `free` at `}`), each with the live memory after it, into `run().bus` (first 1500; `busCut`). The flag is fixed at compile time: without it the closures are the plain ones, so normal runs pay nothing. Keep the event order real: the box appears before its first value, a calculation before the write of its result.
- Errors are `CppError(msg, line, kind)`, `kind` being `'compile'` or `'run'`. On a runtime error `run()` attaches `out`, `trace`, `end`, `cut` and `bus` before rethrowing.

## Language rules (deliberate)

- Only `int` (32-bit wrap) and `int*` pointers to `int` variables (`&a`, `*p`, `nullptr`, `==`/`!=`; no pointer arithmetic, no `int**`, no references). `cout << p` prints a made-up address: `0x1000` + 4 per place on the stack, so a box declared after a `}` gets the address of a box freed there (as the intro says); a pointer to a freed box keeps printing its old address. Using `*p` when p is `nullptr` or its box has left the stack is a runtime error. No arrays, functions, floats, chars, strings. Unsupported things must fail with a friendly Romanian message, never a generic parse error.
- `#include <iostream>`, `using namespace std;` and `int main()` are required, so programs also compile in a real compiler.
- Reading an uninitialised variable is a runtime error (stricter than real C++, on purpose).
- `cin` past the end of input is a runtime error.

## Conventions

- All user-facing text is Romanian, with proper diacritics (ș, ț with comma below) and „ghilimele” quotes. Wording targets a 13-year-old: short sentences, no jargon.
- The highlight overlay depends on the textarea and `#hl` sharing font, 16px/24px line metrics and 12px padding. Change them together (also the `24` and `12` constants in `src/ui.ts`).
- The page must work at phone width and in both light and dark themes.
- Phone view (`@media (max-width:760px), (pointer:coarse) and (max-height:500px)` in CSS, `MOBILE` in `src/ui.ts`; keep them identical): `.wrap` becomes a fixed full-screen app sized from `visualViewport` (`--app-h`/`--app-top`), `[data-pane]` sections show one at a time (`.on`) via the bottom `#tabs` (`start` = the intro, `cod`, `rulare`, `pasi`, `masina` = the machine view, `probleme`, `ajutor`; the problems pane shows either the list or a statement, `.probs.open`), and `#keys` (C++ keys and snippets) appears while the editor is focused. `body.editing` = editor focused, `body.kb` = keyboard open (tabs and explanation hidden). `.tabs`, `.keys`, `.mob` are hidden on desktop. Textareas must stay at 16px or iOS zooms on focus.
- All URLs stay relative (the site is served from `/caiet-cpp/` on GitHub Pages).
- The editor holds one document at a time, chosen in `#ex`: `mine` (the free draft, `caiet.code`/`caiet.inp`), an example (by index, read-only: editing it turns it into `mine`) or a problem (`p<id>`, its own draft in `caiet.p<id>`/`caiet.p<id>.in`). Problems solved on all examples are kept in `caiet.rezolvate`.
- The intro (`#intro`) sits above the editor on a computer until „Ascunde” sets `caiet.intro`; on a phone it is the `start` tab, opened first until then.
